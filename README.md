# 数据产品运营与归因分析平台

面向数据产品运营、渠道归因、用户行为分析、ROI评估、转化优化与数据应用监控的数据分析工程平台。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `data-product-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 活动与 ROI 报告的结算准入链

投放活动与 ROI 报告两条状态链在 `frontend/src/domain/roi-settlement.ts` 里统一定义，
只能按登记方向推进，跨模块写入走 `local-store.ts` 的 `transact` 同事务提交，任一步失败整体退回。

- 活动链：草稿 → 活动审批中 → 投放中 →（已暂停）→ 已结束；报告链：草稿 → 计算中 → 已确认 → 已归档。
- 活动周期口径：只有「已结束」的活动才进入可结算状态，其余状态确认报告一律被阻止并提示
  「活动周期未结束」；活动未结束时不提供正式 ROI 结论（确认页只给试算值）。
- 投入口径：投入金额按核算批次归集（`ACCT-<活动序号>-<两位序号>`），每次「提交计算」为活动
  生成新批次并快照 `日预算 × 已投放天数`（开始日期 → min(结束日期, 今天)）；确认时报告批次
  必须等于活动最近核算批次，否则需重新提交计算。
- ROI 口径：`ROI数值 = (转化收入 − 投入金额) / 投入金额`，确认时生成并冻结；已确认的数值
  不会被后续活动改期、暂停、结束等动作覆盖。
- 活动暂停或结束时，未完成的计算退回草稿并保留核算断点（可继续位置），重新提交计算即可继续。
- 同一活动重复确认、并发生成报告，只接受一份完整结果；已确认报告需先归档才能发起新核算。
- 确认页并列展示活动侧（开始日期、结束日期、活动状态、最近核算批次）与报告侧（投入金额、
  评估周期、最近核算批次、核算断点），逐项列出准入核对结果。
- 旧数据在读取时自动迁移：补齐核算批次字段、按编号对齐关联活动，并把已确认报告的批次
  对齐到活动侧，保证活动与报告两处结果对得上。

`frontend/scripts-test/` 下有两份自测（不进应用包）：领域逻辑用 tsc 编译后跑 node，
服务层用 esbuild 打包后跑 node，覆盖准入链、并发、批次不一致与事务回滚场景。
